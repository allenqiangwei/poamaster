# 圆桌会议功能设计文档

## 产品概述

**产品名称**：COO AI讨论组（圆桌会议）

**目标**：通过智能化的多角色讨论和审查流程，协助COO管理和优化公司战略决策、项目提案及运营方案。AI将作为多角色参与者，提供数据分析、假设验证、决策支持及审查反馈。

**关键原则**：
- 完整实现PRD中的所有功能
- 与现有系统（任务管理、洞察）完全数据隔离
- 部分集成飞书通知和任务创建功能

---

## 一、整体架构

### 1.1 功能定位

圆桌会议作为POA Master的第三个独立工具，与任务管理、洞察系统并列。在工具列表页面新增"圆桌会议"卡片，点击进入独立的功能区。

### 1.2 数据架构

使用独立的数据库Schema，新建以下核心表：

**核心表结构**：
- `RoundtableTemplate`：讨论模板（预置10个，可编辑）
  - id, name, description, scenario, enabled, usage_count, created_at, updated_at
- `RoundtableRole`：角色定义（财务、产品、法务等）
  - id, template_id, name, responsibility, focus_areas, order
- `RoundtableDiscussion`：讨论记录（主表）
  - id, user_id, template_id, title, material_text, status, conclusion, created_at, updated_at
- `RoundtableRound`：讨论回合记录（澄清、质疑、反驳、裁决）
  - id, discussion_id, round_number, round_type, created_at
- `RoundtableMessage`：角色发言记录
  - id, round_id, role_name, content, created_at
- `RoundtableAction`：行动清单
  - id, discussion_id, content, assignee, deadline, acceptance_criteria, priority, task_id
- `RoundtableRisk`：风险清单
  - id, discussion_id, description, impact, mitigation, priority
- `RoundtableAttachment`：上传的文件
  - id, discussion_id, filename, filepath, filetype, created_at
- `RoundtableAssumption`：假设说明
  - id, discussion_id, description, confidence, reasoning

**数据隔离策略**：
所有表使用 `roundtable_` 前缀，与现有的 `tasks`、`insights`、`weekly_topics` 等表完全隔离，确保数据不会交叉污染。

## 二、模板系统设计

### 2.1 预置模板列表（10个）

系统初始化时自动创建以下模板，存储在数据库中：

1. **项目/版本立项提案**
   - 角色：产品经理、技术架构师、财务官、法务官
   - 关注：产品价值、技术可行性、ROI、法律风险

2. **经营数据复盘**
   - 角色：CFO、运营总监、数据分析师、战略顾问
   - 关注：财务指标、运营效率、数据洞察、战略方向

3. **市场投放方案**
   - 角色：市场总监、财务官、品牌经理、数据分析师
   - 关注：投放效果、成本控制、品牌影响、数据验证

4. **运营活动方案**
   - 角色：运营总监、财务官、用户增长专家、风险控制官
   - 关注：用户增长、成本效益、风险控制、活动效果

5. **产品功能评审**
   - 角色：产品经理、用户体验设计师、技术负责人、客服主管
   - 关注：用户需求、体验设计、技术实现、客户反馈

6. **成本削减方案**
   - 角色：CFO、运营总监、采购经理、法务官
   - 关注：成本节约、运营影响、供应商管理、合同风险

7. **组织架构调整**
   - 角色：HR总监、部门负责人、财务官、文化官
   - 关注：组织效率、人员影响、成本变化、企业文化

8. **战略合作评估**
   - 角色：战略顾问、法务官、财务官、业务负责人
   - 关注：战略价值、法律条款、财务影响、业务协同

9. **危机应对方案**
   - 角色：危机管理专家、公关总监、法务官、CEO助理
   - 关注：危机控制、公众影响、法律责任、执行效率

10. **年度规划审查**
    - 角色：战略顾问、CFO、各部门负责人、外部顾问
    - 关注：战略方向、财务规划、资源分配、外部环境

### 2.2 模板数据结构

每个模板包含：
- 模板名称和描述
- 适用场景说明
- 参与角色列表（角色名称、职责描述、关注重点）
- 讨论流程配置（启用的回合类型）
- 风险检查清单（该类讨论需要重点关注的风险类型）
- 输出格式要求（报告需要包含的必填项）
- 自动匹配关键词（用于智能路由）

### 2.3 模板编辑功能

管理员可以通过设置页面编辑模板，修改角色配置、调整讨论流程、更新风险检查项等。支持启用/禁用模板。

## 三、用户交互流程

### 3.1 主界面设计

进入圆桌会议后，顶部显示两个入口按钮：
- **快速开始**：直接输入材料，AI自动选择模板
- **选择模板**：从10个模板中手动选择

### 3.2 快速开始流程

1. 用户输入文本或上传文件（PDF/图片）
2. 显示"正在分析材料..."加载状态
3. AI分析内容，返回推荐模板："已识别为【项目立项提案】，置信度：高"
4. 用户可以确认或手动切换模板
5. 确认后，讨论提交到后台队列处理

### 3.3 选择模板流程

1. 展示10个模板卡片（显示模板名称、描述、参与角色）
2. 用户点击选择模板
3. 进入材料输入页面（文本框 + 文件上传区域）
4. 提交后直接进入后台处理队列

### 3.4 等待页面

提交后跳转到讨论详情页，显示：
- "讨论进行中，预计需要3-5分钟"
- 当前讨论的材料摘要
- 选择的模板和参与角色
- 提示：用户可以离开页面，完成后会收到飞书通知

## 四、AI处理流程

### 4.1 文件预处理

如果用户上传了PDF或图片：
1. 使用OpenAI Vision API (GPT-4 Vision) 处理文件
2. Prompt要求：
   - 提取完整文字内容
   - 识别表格并转换为Markdown格式
   - 识别图表并提供详细描述
   - 提取关键数据点
3. 将提取的结构化内容作为讨论材料

### 4.2 多轮讨论执行

讨论分为4个回合，采用混合调用策略（关键轮次串行，其他并行）：

#### 回合1：澄清回合（并行）

- **调用方式**：一次API调用，让AI同时扮演所有角色
- **输入**：材料内容、模板定义、所有角色信息
- **输出要求**：JSON格式，每个角色提出2-3个澄清问题
- **数据存储**：存储到 `RoundtableRound` 和 `RoundtableMessage` 表
- **目的**：快速了解材料的基本信息和背景

#### 回合2：质疑回合（并行）

- **调用方式**：一次API调用，生成所有角色的质疑
- **输入**：材料内容、澄清结果、角色信息
- **输出要求**：
  - 每个角色的质疑点（风险识别、数据缺失、逻辑漏洞）
  - 假设填充：对缺失数据提供合理假设（标注置信度：高/中/低）
  - 初步风险清单
- **数据存储**：质疑内容存入Message表，假设存入Assumption表，风险存入Risk表

#### 回合3：反驳回合（串行）

- **调用方式**：每个角色独立调用AI
- **输入**：材料内容、之前所有讨论、当前角色信息
- **输出要求**：
  - 基于其他角色的质疑，提出反驳或认同
  - 提供替代方案或补充建议
  - 反对者角色重点发言，提供详细的替代建议
- **调用次数**：根据角色数量（通常4-6次）
- **目的**：确保多维度思考，避免单一视角

#### 回合4：裁决回合（串行）

- **调用方式**：主持/裁决官独立调用
- **输入**：完整的前三轮讨论记录
- **输出要求**：
  - 最终裁决结论（通过/有条件通过/打回/需补充信息）
  - 详细的决策依据和推理过程
  - 完整的行动清单（包含负责人建议、截止时间、验收标准、优先级）
  - 最终风险清单（按优先级排序）
  - 长期战略风险提示
  - 每个参与角色的反馈总结
- **数据存储**：结论更新到Discussion表，行动项存入Action表，风险更新Risk表

### 4.3 调用统计

完整讨论预计API调用次数：
- 文件预处理：0-1次（有文件上传时）
- 模板自动选择：1次（快速开始模式）
- 澄清回合：1次
- 质疑回合：1次
- 反驳回合：4-6次（根据角色数量）
- 裁决回合：1次
- **总计**：8-10次调用

## 五、输出报告与展示

### 5.1 报告数据结构

讨论完成后，生成包含以下内容的结构化报告：

1. **结论摘要**
   - 裁决结果（通过/有条件通过/打回/需补充信息）
   - 核心理由（2-3句话）
   - 关键建议

2. **行动清单**
   - 每项包含：
     - 行动内容描述
     - 建议负责人
     - 建议截止时间
     - 验收标准
     - 优先级（高/中/低）
     - 任务创建状态

3. **风险清单**
   - 按优先级排序（高/中/低）
   - 每项包含：
     - 风险描述
     - 可能影响
     - 建议缓解措施
     - 风险类型（市场/财务/运营/法律/技术等）

4. **讨论过程**
   - 完整的4轮讨论记录
   - 每个角色的发言（带角色标签）
   - 按回合组织展示

5. **假设说明**
   - 数据填充的假设列表
   - 每项包含：置信度、假设内容、假设依据

6. **决策依据**
   - 裁决官的详细推理过程
   - 关键决策点说明

7. **参与角色反馈**
   - 每个角色的专业视角总结
   - 各角色的核心关注点

8. **长期战略风险**
   - 潜在的长期影响
   - 市场趋势变化提示
   - 政策调整风险

### 5.2 报告页面布局

采用富文本报告形式，分为可折叠的区块：

1. **顶部**：结论摘要卡片
   - 高亮显示
   - 带状态标签（通过/打回等）
   - 使用不同颜色区分状态

2. **核心信息区**：
   - 行动清单（左侧或上方）
   - 风险清单（右侧或下方）
   - 支持展开/折叠

3. **讨论过程区**：
   - 按回合展开（澄清→质疑→反驳→裁决）
   - 每个角色发言带标签和图标
   - 支持折叠单个回合

4. **附加信息区**（默认折叠）：
   - 假设说明
   - 决策依据
   - 角色反馈总结

5. **底部操作栏**：
   - 导出PDF
   - 发送到飞书
   - 归档讨论
   - 返回列表

### 5.3 导出功能

**导出PDF**：
- 使用服务端渲染
- 将报告转换为格式化的PDF文档
- 包含完整信息和POA Master品牌标识
- 支持自定义页眉页脚

**发送到飞书**：
- 将完整报告（格式化的Markdown）发送到飞书群聊
- 包含：结论摘要、行动清单、风险清单、讨论过程摘要
- 可选择发送到不同的飞书群组
- 附带查看完整报告的链接

## 六、系统集成

### 6.1 飞书通知集成

#### 场景1：讨论完成通知（自动）

- **触发时机**：讨论处理完成后自动发送
- **通知渠道**：发送到配置的默认飞书群聊
- **消息内容**：
  - 讨论标题
  - 裁决结果（带颜色标识）
  - 关键风险数量
  - 行动项数量
  - 查看链接（跳转到报告页面）
- **消息格式**：使用飞书消息卡片格式，带按钮

#### 场景2：发送完整报告（手动）

- **触发方式**：报告页面"发送到飞书"按钮
- **消息内容**：
  - 完整报告（Markdown格式）
  - 结论摘要
  - 行动清单
  - 风险清单
  - 讨论过程摘要
- **群组选择**：可选择发送到不同的飞书群组（从配置中选择）

### 6.2 任务创建集成

**集成方式**：部分集成，手动触发

**操作流程**：
1. 报告页面的行动清单区块，每一项行动旁边显示"创建任务"按钮
2. 点击后弹出任务创建对话框
3. 预填充任务信息：
   - 标题：行动内容
   - 描述：来自圆桌会议讨论的行动项
   - 负责人：建议负责人（可修改）
   - 截止时间：建议截止时间（可修改）
   - 优先级：继承行动项优先级
4. 用户可以编辑后确认创建
5. 创建后：
   - 在行动项旁边显示"已创建任务"标记
   - 记录task_id到RoundtableAction表
   - 提供跳转到任务详情的链接

**数据关联**：
- RoundtableAction表的task_id字段记录关联的任务ID
- 支持一个行动项创建多个任务（如果需要分解）
- 任务删除不影响圆桌会议记录

### 6.3 历史记录管理

**列表展示**：
- 主页面显示所有历史讨论列表
- 显示信息：讨论标题、模板类型、裁决结果、创建时间
- 使用卡片或表格形式展示

**筛选功能**：
- 按模板类型筛选（10个模板）
- 按裁决结果筛选（通过/打回等）
- 按时间范围筛选（今天/本周/本月/自定义）
- 按状态筛选（处理中/已完成）

**搜索功能**：
- 关键词搜索
- 搜索范围：讨论标题、材料内容、结论内容
- 支持模糊匹配

**操作功能**：
- 点击进入查看完整报告
- 归档讨论（归档后默认不显示，可通过筛选查看）
- 删除讨论（软删除）

## 七、技术实现要点

### 7.1 后台任务处理

**任务队列实现**：
- 使用Node.js的异步处理机制
- 简单方案：内存队列 + 定时器
- 扩展方案：数据库轮询（定期检查processing状态的记录）

**处理流程**：
1. 用户提交后，创建Discussion记录（状态：processing）
2. 将任务ID放入处理队列
3. 后台worker进程从队列获取任务
4. 执行AI调用（4轮讨论）
5. 保存结果到数据库
6. 更新状态为completed
7. 触发飞书通知

**错误处理**：
- 实现重试机制（最多3次）
- 失败后更新状态为failed
- 记录错误信息到discussion表
- 发送失败通知

### 7.2 AI调用实现

**配置管理**：
- 使用现有的OpenAI配置（从settings表读取API Key）
- 支持自定义API Base URL（代理）

**模型选择**：
- 文本理解和多轮讨论：GPT-4o
- 文件处理（OCR）：GPT-4 Vision
- 根据任务类型自动选择

**调用优化**：
- 实现重试机制（最多3次）
- 处理API超时（设置60秒超时）
- 处理Rate Limit错误（指数退避重试）
- Token控制：长文本自动截断或分段处理
- 成本优化：缓存模板和角色定义，减少重复发送

**Prompt工程**：
- 为每个回合设计专门的Prompt模板
- 使用结构化输出（JSON mode）
- 包含示例输出（Few-shot learning）
- 明确角色定义和关注重点

### 7.3 数据安全

**文件存储**：
- 所有上传的文件存储在服务器本地
- 存储路径：`/uploads/roundtable/{discussion_id}/`
- 使用随机文件名（UUID）
- 文件路径记录在RoundtableAttachment表

**访问控制**：
- 讨论内容和报告只有登录用户可见
- 未来可扩展：支持多用户时，只能查看自己创建的讨论

**隐私保护**：
- 敏感信息（如财务数据）不会被日志记录
- API调用日志不记录完整内容
- 文件上传使用HTTPS

### 7.4 性能优化

**列表加载**：
- 讨论列表使用分页加载（每页20条）
- 使用索引优化查询（created_at, status, template_id）

**报告展示**：
- 报告内容使用懒加载
- 折叠区块按需加载内容
- 长文本分段渲染

**文件上传**：
- 单个文件最大10MB
- 最多上传5个文件
- 支持的格式：PDF, PNG, JPG, JPEG
- 客户端验证 + 服务端验证

**缓存策略**：
- 模板配置缓存（减少数据库查询）
- 角色定义缓存
- 历史讨论列表短期缓存（5分钟）

## 八、模板管理与配置

### 8.1 模板管理界面

**位置**：设置页面新增"圆桌会议配置"选项卡

**模板列表**：
- 展示所有10个模板（卡片形式）
- 显示信息：
  - 模板名称
  - 参与角色数量
  - 使用次数（统计）
  - 启用状态
- 操作按钮：
  - 编辑
  - 启用/禁用
  - 查看使用统计

### 8.2 模板编辑器

点击编辑后进入模板配置页面，包含以下部分：

#### 1. 基本信息
- 模板名称（必填）
- 描述（选填，200字以内）
- 适用场景说明（选填，500字以内）
- 启用状态（开关）

#### 2. 角色配置
- 角色列表（可添加/删除/编辑/排序）
- 每个角色包含：
  - **角色名称**（如"财务官"、"产品经理"）
  - **职责描述**（如"评估财务可行性和ROI"）
  - **关注重点**（如"成本、收入、现金流、投资回报"）
  - **显示顺序**（拖拽排序）

#### 3. 讨论流程配置
- 选择启用哪些回合：
  - 澄清回合（必选）
  - 质疑回合（必选）
  - 反驳回合（可选）
  - 裁决回合（必选）
- 可添加自定义回合（未来扩展）

#### 4. 风险检查清单
- 预设的风险检查项列表
- 每项包含：
  - 风险类型（市场/财务/运营/法律/技术/战略）
  - 检查描述
  - 优先级（高/中/低）
- 支持添加/删除/编辑

#### 5. 输出要求配置
- 报告必须包含的字段（勾选）：
  - 结论摘要（必选）
  - 行动清单（必选）
  - 风险清单（必选）
  - 假设说明（可选）
  - 决策依据（可选）
  - 角色反馈（可选）
  - 长期战略风险（可选）

#### 6. 自动路由关键词
- 为模板定义关键词列表（用于智能路由）
- 示例：
  - 项目立项：["立项", "新项目", "项目提案", "版本规划"]
  - 经营复盘：["复盘", "经营数据", "业绩分析", "财报"]
  - 市场投放：["投放", "广告", "市场推广", "获客"]

### 8.3 自动路由配置

**模板匹配设置**：
- 调整模板匹配的优先级（拖拽排序）
- 设置默认模板（当无法匹配时使用）
- 置信度阈值设置（低于阈值时提示用户确认）

**匹配准确率统计**：
- 展示历史自动匹配的准确率
- 显示每个模板的匹配次数和用户调整次数
- 识别需要优化的模板关键词

### 8.4 通知配置

**飞书通知设置**：
- 选择默认的飞书通知群组（下拉选择，从settings中读取配置的群组）
- 配置通知触发条件：
  - 所有讨论完成后都通知
  - 仅高风险讨论通知
  - 仅特定模板的讨论通知
- 自定义通知消息模板（使用变量占位符）

**通知内容模板**：
```

裁决结果：{conclusion}
行动项：{action_count}项
```

**总计**：15-21天

### 9.2 技术风险

1. **AI调用成本**：多轮讨论会产生较多API调用，需监控成本
2. **处理时间**：3-5分钟的等待时间，需要良好的用户体验设计
3. **OCR准确性**：复杂文档可能识别不准确，需要fallback方案
4. **模板自动选择**：AI可能选错模板，需要提供调整机制

### 9.3 成功指标

- 模板自动选择准确率 > 80%
- 讨论处理成功率 > 95%
- 平均处理时间 < 5分钟
- 用户满意度（通过报告质量评估）

## 总结

圆桌会议功能通过AI多角色协作，为COO提供全面、专业的决策支持。设计遵循以下核心原则：

1. **数据隔离**：完全独立的数据架构，确保不影响现有系统
2. **智能自动化**：从文件处理到模板选择，从讨论到报告生成，全流程自动化
3. **灵活可配置**：10个预置模板可编辑，支持自定义
4. **部分集成**：与飞书和任务系统适度集成，保持灵活性
5. **用户友好**：简洁的交互流程，清晰的报告展示

该设计方案完整实现了PRD中的所有功能需求，为后续开发提供了清晰的指引。
